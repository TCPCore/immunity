## 1. Environment reality on this machine (already established, do not re-litigate)

- macOS 15.5 on **Intel Core i7-4790K**, `x86_64`. Docker Desktop (amd64) is being installed.
- System Python is **3.7.9**, far too old. **`uv` is installed** at `~/.local/bin/uv`
  (add `export PATH="$HOME/.local/bin:$PATH"`). A Python **3.12.15** venv already exists at
  `.venv/`.
- ⚠️ **`falkordblite` does not work on this machine.** Every published macOS wheel
  (0.1.0 → 0.10.0) is tagged `macosx_10_13_x86_64.macosx_15_0_arm64` but actually contains
  **arm64-only** `redis-server` and `falkordb.so`. It fails with
  `OSError: [Errno 86] Bad CPU type in executable`. **Do not try to fix this by pip-installing
  other versions or by installing `libomp`, it is an upstream packaging bug, not a
  missing-dependency problem.** Use the Docker container instead.
- Therefore the **only** supported local path is the official container:
  `docker run -d --name immunegraph-db -p 6379:6379 falkordb/falkordb:latest`

### Connection layer requirement

Never hardcode the connection. `src/immunegraph/db.py` must read `FALKORDB_HOST`,
`FALKORDB_PORT`, `FALKORDB_USER`, `FALKORDB_PASSWORD`, `FALKORDB_GRAPH` from the environment
(see `.env.example`). One code path must serve **both** a local container and
**FalkorDB Cloud** (host/port/user/password, TLS off on the free tier), so that if Docker
misbehaves on this old Intel/Sequoia combination we can switch to Cloud by editing `.env`
alone. That is a fallback, not the plan.

## 2. What we are building

**ImmuneGraph, a self-healing memory for AI agent swarms.**

Multi-agent systems have a failure mode that ordinary memory layers do not address:
**hallucination cascades**. One agent invents a false claim, a second derives a plan from
it, a third derives a plan from that, and the swarm acts on a lie. Existing memory stores
*what was said*; it does not notice the swarm is getting epistemically sick.

ImmuneGraph treats every claim, source, agent and derivation as a graph node. Cypher
queries continuously detect circular support, unsupported roots, contradiction clusters and
cascade reach. On detection it creates an `Infection`, dispatches an **antibody agent** that
injects a sourced correction, quarantines the claim, and records the episode, so that the
*next* time a similar claim appears it is flagged instantly. The swarm develops immunity.

### Track 02 alignment (this is the judging rubric, hit it explicitly)

| Track 02 requirement | How ImmuneGraph satisfies it |
| --- | --- |
| Episodic / semantic / procedural memory | `Message`+`Session` / `Claim`+`Source` / `Antibody`+`Infection` (see `docs/GRAPH_MODEL.md` §1) |
| Persistent conversation history | `Message` nodes are append-only and timestamped |
| Shared state and handoffs between agents | one graph is the shared blackboard; `HANDOFF_TO` edges |
| High-concurrency reads and writes | concurrent agent writes; demonstrate with a multi-threaded burst test |
| Separate memory per user or tenant | one FalkorDB graph per tenant via `select_graph("tenant_<id>")` |

### Track 01 alignment

The antibody agent **acts** on connected data: it calls graph queries as tools, chooses a
correction strategy from what the graph shows, and writes the correction back. The Cypher
traversal path *is* the explanation shown to the user ("this claim is quarantined because it
descends 3 hops from a claim with no trusted source").

## 3. Definition of done

A judge can run `docker compose up` plus one command, then watch this sequence end to end:

1. Researcher asserts **"Mars has breathable oxygen at night."** → no trusted source.
2. Q2 flags it **unsupported**. An `Infection` is created.
3. Analyst asserts **"If Mars has breathable oxygen, we don't need helmets."** →
   `DERIVED_FROM` the false claim.
4. Planner asserts **"We can skip life support."** → second-hop derivation.
5. **Q4** computes cascade reach (infected claims, exposed agents) and severity from the
   graph. The dashboard shows the cascade lighting up.
6. An **antibody** injects "NASA: Mars' atmosphere is ~95% CO₂, no breathable oxygen",
   linked via `NEUTRALIZES` + `INJECTS`; the root claim goes `status='quarantined'`.
7. **Q5** shows Researcher's *derived* trust drop.
8. Researcher repeats **"Mars has oxygen at night."** → **Q6/Q7 immunity recall fires
   instantly**, no re-detection of the cascade.
9. `Q8` shows antibody effectiveness across outbreaks.

Nothing is done until a **recorded run** of that sequence exists.

### Non-negotiable engineering gate

`python -m immunegraph.verify_queries` must execute **every** query in
`docs/GRAPH_MODEL.md` against a live instance and pass. **A query that has never been
executed is not a feature.** FalkorDB implements a subset of openCypher, assumption-driven
Cypher is the single most likely way this project fails.

⚠️ Read `docs/GRAPH_MODEL.md` §6 before writing any new Cypher. In particular:
**there is no regex operator**, **no label expressions**, **no aggregation inside pattern
comprehensions**, and **`LIMIT` does not constrain `CREATE`/`SET`/`DELETE`/`MERGE`**.

## 4. Architecture

```
┌──────────────────────────────────────────────────────────┐
│ Streamlit: transcript · live graph canvas · infection     │
│             dashboard · immunity memory                   │
└───────────────────────────┬──────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────┐
│ Orchestrator (Python)                                    │
│  extractor → immune scanner → antibody agent             │
│  (LLM JSON mode + deterministic rule-based fallback)     │
└───────────────────────────┬──────────────────────────────┘
                            │  Cypher only
┌───────────────────────────▼──────────────────────────────┐
│ FALKORDB, Agents · Claims · Sources · Infections ·      │
│            Antibodies · Messages · Sessions              │
└──────────────────────────────────────────────────────────┘
```

### Modules

| File | Responsibility |
| --- | --- |
| `src/immunegraph/db.py` | env-driven FalkorDB connection, schema + index creation, graph reset |
| `src/immunegraph/models.py` | dataclasses + fingerprint normalisation |
| `src/immunegraph/schema.py` | schema DDL kept in sync with `docs/GRAPH_MODEL.md` |
| `src/immunegraph/queries.py` | the Q1-Q8 Cypher, each as a named constant + typed wrapper |
| `src/immunegraph/verify_queries.py` | **runs every query against a live DB; non-zero exit on failure** |
| `src/immunegraph/extractor.py` | message → claims/sources/edges, LLM JSON mode + rule fallback |
| `src/immunegraph/immune.py` | detection passes, Infection creation, severity from Q4 |
| `src/immunegraph/antibody.py` | correction generation, Antibody nodes, quarantine, outcome tracking |
| `src/immunegraph/agents.py` | simulated Researcher / Analyst / Planner with distinct trust profiles |
| `src/immunegraph/demo.py` | the scripted Mars scenario, runnable headless for the video |
| `app.py` | Streamlit UI |
| `tests/` | pytest: fingerprinting, extraction fallback, query smoke tests |

### Extraction resilience (important for demo safety)

`extractor.py` must expose two implementations behind one interface:
`LLMExtractor` (strict JSON schema, few-shot, temperature 0) and `RuleExtractor`
(deterministic keyword/pattern matching). Select via `EXTRACTOR=llm|rule|auto`. `auto`
tries the LLM and falls back to rules on any error or schema violation.
**The graph queries are real in every mode, only the natural-language parsing changes.**
This is the difference between a demo that works on stage and one that does not.

## 6. Guardrails for the agent

- **Never** present an unexecuted Cypher query as working. Run it.
- **Never** invent FalkorDB syntax, track names, prize details, or deadlines. Everything
  needed is in this brief and `docs/GRAPH_MODEL.md`.
- **Never** compute in Python what a Cypher query should compute (cycles, reach, trust).
  The graph must be load-bearing, see Rule 3.
- **Never** commit `.env`, credentials, or the FalkorDB Cloud cookie jar. `.gitignore` covers it.
- Keep `docs/GRAPH_MODEL.md` and `schema.py` in sync in the *same commit* as any model change.
- If a design decision is ambiguous, **stop and ask the human** rather than guessing, the
  human has to be able to defend every choice to a judge (Rule 12).
- Prefer boring, working code over clever code. The deadline is 3 days out.
